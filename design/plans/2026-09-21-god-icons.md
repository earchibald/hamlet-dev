# Give each god its own icon

Playtest recommendation 2 (playtest notes of 20 Sept 2026, seed amber-ford-45). Every god is drawn as the same gold star, `SPECIES.god.glyph` (`✶`). The player cannot tell one god from another, or one god's acts from another's. This plan draws one pixel icon per kind of god, keyed by the god's `pole`, and uses it everywhere the interface shows a god.

| Task | What | Files |
|---|---|---|
| 1 | The icon table and its three drawing helpers, with fast tests | `src/ui/icons.js`, `src/ui/index.js`, `tests/icons.js`, `package.json` |
| 2 | The icon on the canvas: the ages view, and a sleeping god in the nearby and local views | `src/ui/map.js`, `tests/icons.js` |
| 3 | The icon in the page: the god's card, the window title, the people row, the timeline lane, the act caption | `src/ui/inspect.js`, `src/ui/windows.js`, `src/ui/panels.js`, `src/ui/timeline.js`, `src/ui/actions.js`, `src/ui/map.js`, `src/page.template.html`, `tests/icons.js` |

## Rules for every task

- This is interface work only. Nothing in `src/sim/` changes. The soak golden must not move.
- A god's kind is `g.pole`, one of the ten keys of `POLES` in `src/sim/marks.js`: above, below, wet, dry, hot, cold, still, moving, light, dark. Read the icon by `pole`. Never read the god's name.
- The icons are pixel art. Draw every art pixel at integer coordinates, with no smoothing, so the edges stay sharp at 1x and 2x.
- The icon colours are fixed, the same in both themes. The outline makes each icon readable on any field colour.
- `src/ui/icons.js` touches no DOM at load time. A helper may reach for `document` inside its body only.
- `tests/ui.js` is behind `SLOW=1` until G4 finishes, so a test there does not run in the fast suite. Put every new test in `tests/icons.js`, and add that file to the `fast` script in `package.json`.
- Run `node build.js` after each change to `src/`. Run `node --test tests/icons.js` and `npm run fast` before each commit.
- Keep the star as the fallback: a record with no known pole draws `SPECIES.god.glyph` as before.

`GOD_OUTLINE` is one fixed dark ink, `#15171c`.

Three helpers:

1. `godIconCells(pole)` returns `null` for an unknown pole. Otherwise it returns the cells of an 11 by 11 grid. The art is at offset 1,1. An outline cell goes on every empty cell that touches a filled cell on one of its four sides. Each cell is `{ x, y, fill }`. Compute it once per pole and keep the result.
2. `drawGodIcon(ctx, pole, cx, cy, s)` draws the cells centred on `cx, cy`, `s` screen pixels per art pixel, with `fillRect` at integer coordinates. It returns `false` and draws nothing for an unknown pole, so the caller can draw the star.
3. `godIconSvg(pole, size, label)` returns an SVG markup string, `viewBox="0 0 11 11"`, `shape-rendering="crispEdges"`, one `rect` per cell. With a label it has `role="img"` and `aria-label`; without one it has `aria-hidden="true"`. It returns `''` for an unknown pole. The label is escaped with `esc` (`derive.js`).

Tests in `tests/icons.js` (load the UI files with the same `loadUI` shape as `tests/ui.js`):

- The keys of `GOD_ICONS` equal an explicit list of the ten poles, and also equal `Object.keys(POLES)`.
- Each art has 9 rows of 9 chars from `.abc`, and each palette has three `#rrggbb` colours.
- The ten arts are all different.
- Every outline cell is empty in the art and touches a filled cell. Every empty cell that touches a filled cell is an outline cell.
- `drawGodIcon` on a recording context: every `fillRect` has integer arguments, the count equals the cell count, and the drawn box is centred on `cx, cy` within one pixel. An unknown pole returns `false` with no calls.
- `godIconSvg` has one `rect` per cell, and escapes a label that holds `<`.

Break each helper once by hand and watch its test fail before you commit.

## Task 2: the icon on the canvas

In `drawField` (`src/ui/map.js`), where each god's star is drawn, draw `drawGodIcon(wctx, s.g.pole, s.x, s.y, 2)`, and fall back to the star if it returns `false`. The icon is 22 px across. Move the name label below it, and widen the nudge that keeps two gods apart to the icon's width. Keep the alpha of an asleep god and of a god that fades out.

In `drawMid` and in the local view, a live god draws its icon in place of the glyph. Use scale 1 in the nearby view (tile 9 px) and scale 2 in the local view (tile 26 px). Every other being draws as before. The comment on `beingGlyph` names the star, so rewrite it.

Test in `tests/icons.js`: drive `drawField` the way `tests/ui.js` does near line 1968, with a real creation and a recording canvas. Wrap `drawGodIcon` to record its calls. Every god that `drawField` places gets one call with its own pole, and no `fillText` call draws `✶`. Confirm that this test fails on the code before the change.

## Task 3: the icon in the page

- The god's card (`inspectGod` in `src/ui/inspect.js`): the icon at 22 px before the name.
- The window title of a god's card (`src/ui/windows.js`): the icon at 16 px before the name.
- The people row of a god in the ages (`src/ui/panels.js`): the icon at 14 px before the name.
- The timeline lane (`src/ui/timeline.js`): the icon at 14 px before the lane label when the lane is one god. `timeline.js` builds nodes and never uses `innerHTML`, so use an `img` whose `src` is a `data:image/svg+xml` URL of `godIconSvg`, with an empty `alt`. Find out from `timelineModel()` in `derive.js` whether a row names its god; if it does not, add the god's id to the row.
- The act caption: show the icon of the god of the act on stage before the caption text. `setActCaption` in `src/ui/actions.js` takes the pole as a second argument and keeps it with the text, so the page is written only when either one changes. `drawField` passes it. The icon is decoration here (`aria-hidden`): the caption text already names the god.
- CSS in `src/page.template.html`: an icon sits on the text baseline, `vertical-align: -2px`, `image-rendering: pixelated`, and a small gap after it.

No player text changes in this plan. The only new words are the `aria-label` of an icon, which is the god's name and epithet, already shown.

Tests in `tests/icons.js`: `inspectGod` of a god from a real creation holds that god's icon markup. `setActCaption` with the same text and a new pole writes the page again.
