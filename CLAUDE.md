# Hamlet (working title: Hearth)

A small Dwarf-Fortress-style simulation. Read `design/notes.md` first. It holds the design, the rules that were tuned by testing, and the bugs already found and fixed. Do not re-derive them.

## Layout
- `src/sim/`: the simulation core. No DOM. Everything that decides what happens. It is plain scripts that share one scope, joined in the order in `src/sim/index.js`. One file per system: core (constants, tables, state, and the chronicle), clock (the calendar, the units, and every duration and rate), names (the name record, the old tongue, the namer, and the layout guard), field (the countries and their boundaries), marks (what a god did to a country), world, path, camps, tasks (the TASKS table, the tick executor, and human work), beings, species, fae, goals, recipes, weather, gods (the primal gods and the ages), settle (from marks to tiles), main, door. `door.js` is the one way in from outside: `inject(event)`.
- `src/sim/index.js`: the manifest. `source()` joins the files for the page. `load()` runs them in Node for the tests.
- `src/sim/recipes.js`: crafts as data. Add a recipe, get a goal.
- `src/sim/snapshot.js`: the whole world as plain JSON. `REFS`, `takeSnapshot()`, `loadSnapshot(snap)`. The door's `load` act calls `loadSnapshot`.
- `src/ui/`: the canvas interface. Reads state, draws, handles tools. Never changes the rules. Plain scripts in one scope like `src/sim/`, joined by `src/ui/index.js`. `derive.js` and `keys.js` have no DOM and are tested in `tests/ui.js`, though `derive.js` calls `setFocus` from `actions.js`, so a test that drives it must load `actions` too. View state changes in `actions.js`, with six recorded exceptions: the window drag handler in `windows.js`, the palette's own list state in `dialogs.js`, the cursor and hover set by the pointer handlers in `main.js`, and the beat clock (`acc`, `ui.playing`, `beatsLastFrame`) driven by the frame loop in `main.js`. The fifth exception is the gods' map cache in `map.js`. `drawField`, `drawFieldCache`, and `readPalette` write its fields: `fieldKey`, `fieldAge`, `fieldGestures`, `fieldDiscards`, `fieldSkip`, `fieldJump`, and `fieldPreview`. The sixth exception is the zoom's skip flag, `zoomSkipConsumesClick`. Three handlers in `initUI` in `main.js` write it: the capture listeners for pointerdown and click, and the keydown handler. `ui.chronFilter` is written by the drawer pointer handler in `main.js`, and by `restore()` in `state.js`, which writes it with every other persisted view field when it reads the saved state. `ui.focus` is not an exception: `setFocus` in `actions.js` is its one writer, and every file but `actions.js` calls it. An exception here names a field and the function that writes it, so that a grep can settle whether the line is still true. Naming only a file grants more than it means to. `preview.js` models the ground that the gods' marks will become, and the gods' map is drawn from it. It has no DOM, draws no random number, and writes no state. `tests/preview.js` loads it in Node.
- `src/page.template.html`: the page shell. `__SIM__` and `__UI__` are replaced by `build.js`.
- `dist/hearth-sim.html`: the built single file. It is published to two public sites. Every push to `dev` publishes it to the dev site at https://earchibald.github.io/hamlet-dev/. `.github/workflows/pages.yml` rebuilds the page and copies it to `index.html` at the site root. So a merge into `dev` changes a public site, with no further step. A versioned release publishes it to https://earchibald.github.io/hamlet/ from `main`: see "Rules of release" below. It is no longer published as a Claude artifact. Keep it working. Run `node build.js` after every change to `src/`. Run `npm install` once before the tests. `tests/types.js` needs TypeScript, and it skips without it, so nothing is type-checked.
- `tests/soak.js`: six seeds for 70 days, with assertions and a golden record. Run it after every change to the core. If the numbers moved and the move is what you meant, bless them with `UPDATE_GOLDEN=1 node tests/soak.js`.
- `tests/lib/run.js`: the shared runner. The script god, the event collector, the counters, the fingerprint, and `setClock`.
- `setClock(api, at)` in `tests/lib/run.js` is the one function that sets the world's date. A test may jump to a date rather than pay the days to reach it. It lives in the tests and never in `src/sim/`, because a rule reachable only through a back door in the product is a rule the product can lose without a sound. It writes the world's `tick`, and it moves every accrual marker with it. An accrual marker is a tick on a record whose gap to the present is multiplied into a quantity. There are two: `seen`, the tick a being's body was last brought up to, and `worked`, the tick the job it holds last had work put into it. That is why the function must be used rather than assigning `api.tick`: a clock shoved ten days forward charges every being ten days of hunger it was never alive for, and a jump of one world hour once put 3,600 ticks of work into a snare nobody touched. Nothing else moves, and nothing accrues across a jump. A deadline already set is left where it is and so expires, which is what an arrived world would also have done. `tests/setclock.js` holds both halves, and keeps an inventory of every elapsed gap the rules read, so a rule that adds a new one goes red there. A test that sets the date proves a rule runs at that date; it does not prove the date is reachable by playing, and the suite owes one run that arrives by simulating.
- `tests/terrain.js`: the levels, slopes, and hills. Fast. Run it with the soak.
- `tests/crafts.js`: each recipe through the real offers. Fast.
- `tests/garden.js`: gardenLives against the old whole-map scan, for a hand-built garden and for a real run. The five hand-built cases are fast. The two real runs ask 15 world days, take 133 s, and run behind `LONG=1`. A camp plants its first garden on day 5.6, so a shorter run tests nothing and the guard says so.
- `tests/names.js`: the name record, the two streams, the old tongue, the namer, who names what and when, epithets and fate, and the layout guard against a moved being or item. Fast.
- `tests/ui.js`: the view model in both eras, the stages, the key map, every button has a key, the mark rows, and that a watched creation equals an unwatched one. Run it after every change to `src/ui/`.
- `tests/preview.js`: the preview of the ground on the gods' map. That `previewField()` draws no random number and writes no state. That each act shows on the map at once. That the preview looks like the settled valley on the six soak seeds. That the gods' map is drawn in the preview's colours. That the preview is computed once per act. That no text the player reads says "country". Fast.
- `tests/zoom.js`: the pure zoom model in `src/ui/zoom.js`. The three frames, the camera at each fraction of a leg, a plan's legs, and its clock. The alphas at a fraction, the settle's four stops, and the guard that only `actions.js` writes `zoom`, which `state.js` declares. Two checks on the source text of `main.js`. The frame loop steps the world only when no zoom runs. The keydown handler ends a running zoom before it acts on the key. Fast.
- `tests/people.js`: the People drawer's two filters, camp and age. The rows each filter keeps, the order in which each button steps through its values, the count, the labels, the window title, the empty text, the saved age, and the E and Y keys. These tests are here and not in `tests/ui.js`, because that file runs only with `SLOW=1`. Fast.
- `tests/trails.js`: the motion trail. The squares a creature crosses, kept in order, and the limit on their number. A new trail after a jump, and none for a god. The fade of each dot and the prune. The clearing of every trail on a load, on the Hour button, and on leaving the world map. The call after each step in the frame loop and after the Step button. Fast.
- `tests/icons.js`: the icons of the ten kinds of god. Their table and outline, and the helpers that draw them on a canvas and as SVG. The icon on the map, the god's card, the people list, the timeline and the caption. Fast.
- `tests/gnomes.js`: the gnomes, their burrows, and their mushrooms. Fast.
- `tests/wanderer.js`: the valley after the last person. The line that says the people are gone, the wanderer who comes, and winter. Fast.
- `tests/lightning.js`: the first fire from the sky. Seed moss-crag-87 runs with no god, and nobody lights the pit. A strike near the camp, an ember fetched from it, and the first hearth must come within three storm gaps of the pit being laid. The gap is the mean time between storms that bring a strike, from `CLOCK`. That run stops at the first hearth and takes about 4 s.

  A second test computes how long a cold camp waits for a strike, from `CLOCK` and the weather model. The mean over the year must be close to 2.5 days, the design's figure.

  Hand-built checks follow. Lightning strikes the one pine that people can reach. The goal offers no ember from a fire that nobody can reach. A founder far from the camp still fetches the ember. A first fire lit by moss or by firestones brings newcomers, and its line says the camp has a hearth. A door act or a load inside a tick clears the cached reach, so no stale result is left. Fast.
- `tests/closing.js`: the cave goals, den contention, site scoring, and lightning. Fast.
- `tests/door.js`: every act through `inject()`, logged whether it lands or not. Fast.
- `tests/options.js`: world size and the level range at start. Fast.
- `tests/ages.js`: twenty-four seeds run the creation to settle, with a report. The tuning tool for the grammar of the ages. Fast.
- `tests/settle.js`: the painters, the founding sites, the creatures, the bodies, and the tile check. Fast.
- `tests/clock.js`: the unit helpers, the table's values, and a lint: no bare time literal in a rule. Fast.
- `tests/tasks.js`: the table, the executor, that every task and offer is plain data, and that no file holds a closure task. Fast.
- `tests/beats.js`: the cellular beat. That it is a minute of world time, that each of the six systems runs 1,440 times a world day and names the tick of its next beat, that the beat leaves the world's rates where they were, and that every period nested inside it is a multiple of it. Fast.
- `tests/beings-lazy.js`: a being's body off the tick. `catchUp` against the old head, transcribed and stepped one tick at a time, for a sleeper across a dawn, a starving person, a freezing one, and a season's turn. The sleeper roused by fire or by a hunter, and the budget for a world day. Fast.
- `tests/setclock.js`: `setClock` in `tests/lib/run.js`. That a jump moves every accrual marker, that it puts no work into a job, and an inventory of every elapsed gap the rules read. Fast.
- `tests/itemgrid.js`: after a removal, the item grid matches a full rebuild, slot for slot, including a stacked tile. The stacked-tile case is fast. The two real runs ask 5 world days, take 347 s, and run behind `LONG=1`. The real runs also count how many items enter and leave, because a run too short to exercise `removeItem` used to pass in silence.
- `tests/stalk.js`: the wolf's lone-person pick, against the old expression, hand-built and through a real run. The whole file takes 92 s and needs no flag. The real runs ask 15 world days, because a stale cache shows only when the cast of nearby people changes. That cast changes nine times in fifteen days, and not at all in four hours.
- `tests/reachable.js`: the flood fill matches an old Set-based reference, member for member and in the same order, across seeds, starts, and caps. Fast.
- `tests/snapshot.js`: the streams, `REFS`, `takeSnapshot()`, `loadSnapshot(snap)`, the oracle (save mid-run, load, run on), and the guard that every top-level `let` or `var` is saved or listed with a reason, and every top-level `const` container is named or listed as frozen. The guards are fast. The oracle runs behind `SLOW=1` and takes 1,120 s. Each save point is measured, and each one asserts what its own comment claims, because a comment alone cannot fail.
- `tests/types.js`: runs `tsc --checkJs` on `src/sim/` through `tsconfig.sim.json`, and fails on any error. It also runs `tsc` on `tsconfig.probe.json`, a fixture with a misspelt field on a Being, a Tile, a GroundItem, and a Camp, read both directly (`makeBeing()`, `makeTile()`) and through the shared state (`beings[0]`, `tileAt()`, `items[0]`, `camp`), and fails unless every one is still caught, so a type this loose cannot come back unnoticed. Both checks skip, with a message that names what is not being checked, if TypeScript is not installed. `src/ui/` is not part of this test yet: see `tsconfig.ui.json` below. `npm run types` alone is not a gate. If an annotation is lost, the variable falls back to `any`, its errors vanish, and `npm run types` still reports zero. Only the probe test sees that, so run `node --test tests/types.js`. Fast.
- `tsconfig.sim.json`: the type check for `src/sim/`, at zero errors today. No DOM in its `lib`, which proves the rule that the sim core has no DOM.
- `tsconfig.ui.json`: the type check for `src/ui/`, loaded together with `src/sim/` because the two share one scope in the built page. Not yet at zero errors, and not run by any test: 101 errors remain, in main.js, panels.js, windows.js, dialogs.js, keys.js, and actions.js, almost all DOM narrowing (a value tsc sees as `Element` or `EventTarget` used where `HTMLElement`'s `.dataset`, `.value`, `.closest`, or `.style` is read). The next session that picks this up should start there.
- `tsconfig.probe.json`: checks `types/probe/misspelled.js` together with `src/sim/`, for `tests/types.js`'s own guard. Never part of the build, of `dist/`, or of `tsconfig.sim.json`.
- `types/sim/`, `types/ui/`, `types/probe/`: JSDoc types are not written into `src/`, because `build.js` copies comments verbatim into `dist/hearth-sim.html`, and these folders hold the shapes instead, in `.d.ts` and `.js` files with no `import` or `export`, so they join the same global scope as `src/sim/` and `src/ui/`. None of the record interfaces in `types/sim/` carries a catch-all index signature, because one hid a misspelt field from tsc; `cooldown` on a Being keeps the one index signature that is genuinely a map with no closed set of keys. The one `let` in `src/sim/core.js` that holds the shared state (`world`, `levels`, `beings`, `items`, `camp`, and the rest) carries an inline JSDoc `@type` per variable, because an interface alone checks nothing if the array or the global holding the records is untyped; a handful of lookup functions built on that state (`tileAt`, `itemAt`, `beingById`, `campHumans`, `campNear`) carry a `@returns` for the same reason. Each of these is comment-only and marked as such in the type-checks proposal record.
- `npm run fast` runs them all.

## Rules of work
- Write in plain English in the game's text. One idea per sentence.
- Rules read data tables (materials, species, goals). Rules do not check names.
- Every new behaviour must be visible to the player: a chronicle line, a thought, a goal state, or a tooltip row.
- Any death in a 70-day soak that is not old age is a bug until proven otherwise. Trace it with `tests/trace-deaths.js`.
- The engine step is pure. Every outside act enters by `inject()` in `src/sim/door.js` and is logged. A seed, its options, and its log replay the same story.
- A duration or a rate goes in `CLOCK` in `src/sim/clock.js`, or in a `SPECIES`, `LIFE`, or `RECIPES` row written in the unit helpers or in days. `tests/clock.js` fails on a bare one.
- A task is a plain record. Its behaviour goes in `TASKS` in `src/sim/tasks.js`. Name a thing by id or by coordinates, never by reference.
- A field that points at another record goes in `REFS` in `src/sim/snapshot.js`. `tests/snapshot.js` fails on one that is missing.
- A new top-level `let` or `var` in `src/sim/` goes in `SAVED_STATE` or `NOT_SAVED` in `src/sim/snapshot.js`. A new top-level `const` that holds a container goes in `KNOWN_CONSTS` or `FROZEN_TABLES` in `tests/snapshot.js`.
- State lives in plain objects and arrays. A `Map` or a `Set` a snapshot must save is a fault the guard reports.
- Naming moves no being and no item, adds no thought, and changes no need; only `chronicle` and `chronicleLines` may move for naming work.
- A rule never reads a name's text to decide anything. It reads data tables instead.
- Text a player reads, and developer documentation, goes through a review panel before it lands. Dispatch three or more Sonnet reviewers on the text alone. Each one judges three things: does it sound human, is it plain English, is it readable. Rewrite on their findings. This applies to every element of gameplay, not only to a batch of new phrases.

- Execute a plan with subagent-driven development. A fresh implementer per task, a task review after
  each, and a broad review of the whole branch at the end. Do not ask which mode to use, and do not
  execute a plan inline: the per-task review is what caught the two Criticals in Become E1 task 4 and
  the four production changes made to satisfy bad tests in E2 task 3.
- Name a file by its absolute worktree path in chat, in a report, in a review finding, in a PR body,
  and in a message to another session. A bare relative path opens the primary clone, which is the
  wrong copy. Inside these documents, repo-relative paths are correct and stay.

## Rules of the split
- Files in `src/sim/` are not ES modules. They share one scope. Do not add `import` or `export`.
- Load-time order matters three times: `core.js` first, `clock.js` directly after it, and `tasks.js` before `beings.js`, `species.js`, and `fae.js`, which add kinds to `TASKS`.
- `updateWorld()` in `main.js` calls the per-tick steps in a fixed order. The order fixes the random number stream. Do not reorder it.
- Passability, search, and fire read levels. A tile has a z. Use `tileAt(x, y, z)`, `passable(x, y, z)`, and `near(a, b)` for beings. Do not index `world` for anything that can be off the surface.

## Rules of release
- The released site is https://earchibald.github.io/hamlet/. Read `version.json` at that address to see which version the site shows.
- The main-coordinator session owns `main`. No other session pushes to `main`.
- `main` moves only by fast-forward to a commit that is already on `dev`. Nobody commits on `main`. If `main` has a commit that `dev` lacks, merge `main` into `dev` first.
- A release starts as a pull request into `dev`. It changes `version` in `package.json` and adds a section to `CHANGELOG.md` under the heading `## vX.Y.Z (date)`. Dev-coordinator merges it. Then main-coordinator moves `main` to that merge commit and pushes.
- The push runs `.github/workflows/release.yml`. It builds the page, runs the fast suite, and makes the tag `vX.Y.Z` and a GitHub Release. The release notes are that version's section of `CHANGELOG.md`. The workflow attaches the built page to the release. The job fails before it builds if `CHANGELOG.md` has no section for the version, or if the tag is already on another commit.
- A second repository, `earchibald/hamlet`, publishes the site. Each repository has one Pages site, and this repository's site is the dev site. Its `deploy.yml` downloads the page attached to the latest release and publishes it. No token is stored, so `release.yml` cannot start that job. Start it by hand after a release: `gh workflow run deploy.yml --repo earchibald/hamlet`. A timer also starts it twice an hour.
- Write a `CHANGELOG.md` section for a player first: what changed in the valley and on the screen. Put changes to the engine and the tests last. It is text a player reads, so it goes through the review panel.
- The version has three numbers. Raise the third for fixes. Raise the second when a player gets something new. Raise the second also when an old save or an old seed no longer plays out the same way. The first stays at 0 until the user says the game is version 1.
- `release.yml` does not run the soak. Run `node tests/soak.js` by hand on the commit before `main` moves to it. A skipped test shows as passing, so read the count of skipped tests in the run summary.
